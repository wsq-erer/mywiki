### iptable
一、 核心参数分类拆解

**1. 基础操作指令**

+ `**-A**` (Append)：追加规则到链的末尾。
+ `**-I**` (Insert)：插入规则（默认插到第 1 条，也可以指定位置如 `-I INPUT 2`）。
+ `**-D**` (Delete)：删除指定规则。
+ `**-L**` (List)：查看已有规则。
+ `**-F**` (Flush)：清空规则。

**2. 核心四大表与常用五大链**

+ `**-t**` (Table)：指定表（默认为 `filter` 表，其他常见有 `nat`、`mangle`）。
+ **常用链 (Chain)**：
    - `**INPUT**`：发往本机的流量。
    - `**OUTPUT**`：本机发出的流量。
    - `**FORWARD**`：经由本机转发的流量（路由器/网关场景）。
    - `**PREROUTING**`** / **`**POSTROUTING**`：路由前/路由后（主要用于 NAT 改写地址）。

**3. 常用匹配条件（Filter）**

+ `**-s**` (Source)：源地址（IP/网段）。
+ `**-d**` (Destination)：目的地址（IP/网段）。
+ `**-i**` (In-interface)：入站网卡接口（如 `-i wlan0`）。
+ `**-o**` (Out-interface)：出站网卡接口（如 `-o rmnet_data+`）。
+ `**-p**` (Protocol)：协议类型（`tcp`、`udp`、`icmp` 等）。
+ `**--sport**`** / **`**--dport**`：源端口 / 目的端口（配合 `-p tcp/udp` 使用）。
+ `**-m**` (Match Module)：加载扩展模块（如 `-m quota2` 配额、`-m state` 状态、`-m mac` MAC地址）。
+ `**!**`：非 / 取反（如 `! -o eth0` 表示除 eth0 以外的所有网卡）。

**4. 处理动作 (Jump Target)**

+ `**-j**` (Jump)：跳向指定的目标动作或自定义链。
    - `**ACCEPT**`：允许放行。
    - `**DROP**`：直接丢弃（静默拒绝，对方无回应）。
    - `**REJECT**`：明确拒绝（主动回复 ICMP 不可达信息）。
    - `**DNAT**`** / **`**SNAT**`：目标/源地址转换。
    - **自定义链名**：跳转到其他链继续处理。



拿到一条长命令时，建议按以下顺序拆解：

1. **看作用点**：先看 `**-A/I**`** 后面跟的链** 以及 `**-i/-o**`** 网卡**（判断流量在什么环节、从哪来去哪）。
2. **看过滤条件**：找 `**-s**`（谁发起的）、`**-d**`（发给谁的）、`**-p/--dport**`（什么协议/端口）。
3. **看最终命运**：找 `**-j**`（是放行 `ACCEPT`、静默扔掉 `DROP`、还是拒绝 `REJECT`）。

三、 实战公式推导

**公式：**`iptables [操作] [链] [匹配条件...] -j [处理动作]`

+ **例 1：**`iptables -A INPUT -s 192.168.1.100 -j DROP`
    - 操作/链：追加到发往本机的流量（`-A INPUT`）。
    - 匹配条件：源 IP 是 `192.168.1.100`（`-s 192.168.1.100`）。
    - 动作：静默丢弃（`-j DROP`）。
    - **含义**：黑名单——禁止 192.168.1.100 访问本机。
+ **例 2：**`iptables -A OUTPUT -o wlan0 -p tcp --dport 80 -j ACCEPT`
    - 操作/链：追加到本机发出的流量（`-A OUTPUT`）。
    - 匹配条件：经由 `wlan0` 网卡（`-o wlan0`）、TCP 协议（`-p tcp`）、目标端口 80（`--dport 80`）。
    - 动作：放行（`-j ACCEPT`）。
    - **含义**：允许本机通过 Wi-Fi 发起 HTTP (80) 网页访问。

```php
default dev rmnet_data1  scope link  metric 400
```

1. `default`（目标网段）
+ **含义**：等同于 `0.0.0.0/0`，即**全网默认路由**。
+ **解析**：所有没有命中其他更精确网段规则（如 `192.168.x.x` 或 `10.x.x.x`）的数据包，全部匹配此项（兜底处理所有外网流量）。
2. `dev rmnet_data1`（出站网卡接口）
+ **含义**：指定数据包从 `rmnet_data1` 网卡发出去。
+ **解析**：`rmnet_data1` 是高通蜂窝基带（4G/5G 模组）的逻辑数据通道，通常承载该设备的主外网 APN 数据链路。
3. `scope link`（链路直连作用域）
+ **含义**：链路直连（Link Scope）。
+ **解析**：表明该接口是**点对点网络链路（P2P）**。内核发包时**无需指定下一跳网关 IP（**`**via x.x.x.x**`**）**，直接将封装好的 IP 数据包推入 `rmnet_data1` 接口即可送达基站。
4. `metric 400`（优先级度量值）
+ **含义**：路由开销与优先级权重。
+ **解析**：**数值越小，优先级越高**。
    - 系统中同时存在另一条 `default dev rmnet_data7 ... metric 500`；
    - 因为 `400 < 500`，所以系统在正常情况下将 `rmnet_data1` 作为**第一主选外网出口**；只有当 `rmnet_data1` 掉线或失效时，才会轮到 `metric 500` 的备用出口生效。



```php
10.166.165.40 dev rmnet_data0  scope link  src 10.227.11.53  metric 10
```

1. `10.166.165.40`（目标 IP / 主机路由）
+ **含义**：没有带子网掩码（等同于 `/32`），代表**单台具体的主机/服务器**。
+ **解析**：只有目的地严格为 `10.166.165.40` 的数据包才会匹配此条规则。通常这是运营商的核心业务服务器（如 IMS/SIP 语音网关、OTA 升级节点、专网 DNS 或集中管控平台）。
2. `dev rmnet_data0`（出站网卡）
+ **含义**：指定数据包必须从蜂窝专网接口 `rmnet_data0` 发出。
+ **解析**：即使系统存在默认外网出口（`rmnet_data1` / `rmnet_data7`），访问该目标时也必须绕开公网通道，走专用的蜂窝专网 APN 通道。
3. `scope link`（直连范围）
+ **含义**：链路直连作用域。
+ **解析**：告诉内核该目标在点对点蜂窝链路上直接可达，**不需要额外的下一跳网关中转（via IP）**，封装好数据包直接推入网卡发送。
4. `src 10.227.11.53`（强制优选源 IP）
+ **含义**：指定发出数据包的**源 IP 地址（Source IP）**。
+ **解析**：当前设备有多个网卡和多个 IP（如 `192.168.1.10`、`10.17.52.115` 等）。当本机系统主动向 `10.166.165.40` 发起通信时，内核会自动将 IP 报头里的源地址填为 `10.227.11.53`，确保运营商对端能正确识别身份并原路返回响应。
5. `metric 10`（度量值 / 极高优先级）
+ **含义**：路由开销权重。
+ **解析**：数值为 `10`（远小于默认路由的 `400` 和 `500`）。这确保了凡是访问该服务器的流量，拥有**最高优先级**，绝对不会走偏到其他外网出口。

网络配置

 1. `ip rule` / `ip route` —— **路由层（寻路与选路）**

 2. `iptables` —— **防火墙 / 过滤层（安全检查站）**

****

当一个数据包进入设备后：

1. **路由层（**`**ip rule**`** / **`**ip route**`**）**：先查路由表，确定该数据包是发给本机的、还是需要转发给其他网卡的、还是直接命中 `blackhole` 丢弃。
2. **防火墙层（**`**iptables**`**）**：确定好去向后，进入对应的链（`INPUT` / `FORWARD` / `OUTPUT`）进行安全策略匹配与拦截。
